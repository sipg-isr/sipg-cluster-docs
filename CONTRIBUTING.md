# Documentation Contributions

- Keep this README concise and use it as the public documentation index.
- Put account-request and availability guidance under `docs/access/`.
- Keep every page suitable for unrestricted public access. Do not include
  credentials, personal data, internal hostnames or addresses, unpublished
  datasets, or restricted procedures.
- Keep user instructions durable and concise. Put transient project-status
  updates in Git history or the owner-managed audit catalog, not user-facing
  pages.
- Describe access requirements and approval conditions, not time-sensitive
  readiness snapshots. Direct readers to the approved contact route for
  current availability.
- Use short, descriptive filenames and add a folder only when it groups related
  pages.
- Do not add a license or publish a specific account-request route until the
  responsible owner has approved it.
